## 1. 项目概述

### 1.1 一句话定义

Seedcast（飞播）是一个**开源、免费、纯本地**的多平台内容发布桌面工具：一份内容，像种子一样播撒到多个创作平台。平台能力以**插件**形式扩展，新增平台 = 开发一个插件。

### 1.2 命名与标识（已定）

| 项 | 值 | 备注 |
|---|---|---|
| 产品名 | Seedcast | seed + broadcast；中文名"飞播"（取"飞播造林"，飞机撒种、一处播撒处处生长） |
| 仓库名 | seedcast | npm 未占用，GitHub 几乎无同名项目（已筛查） |
| 包命名空间 | `@seedcast/*` | engine / app / plugin-* |
| 数据目录 | `~/.seedcast/` | 账号会话、内容库、记录、第三方插件 |
| Tauri identifier | `com.seedcast.app` | |
| 许可证 | **Apache License 2.0** | 免费开源，允许商用；见仓库 `LICENSE` |
| 代码目录 | `code/` | 应用/引擎/插件源码均在此；规划文档可在仓库根 `docs/` |
| 远程仓库 | https://github.com/owlteam990/seedcast | **第一版完成前不 push**；本地可先 `git remote add` |

### 1.3 背景与立项依据

对两个商业竞品（蚁小二 yixiaoer.cn、TurboPush turbopush.top）的公开资料与源码研究（证据见附录 A）表明：

1. **技术门槛不高，护城河是维护**。两者核心都是"真实账号会话 + 按平台适配器"。TurboPush v2.3.4 更新日志几乎全是"小红书/B站封面改版适配"——平台前端一改，适配器就断，商业公司靠养团队持续修。
2. **两条路线**：蚁小二云端执行（`POST /api/taskSets/v2`，cloud/local 双通道，账号分 Crawler/OpenPlatform/Overseas 三类）；TurboPush 纯本地执行（Tauri 壳 + 本机 Chrome/Edge + 本地 HTTP/SSE API + 开源 MCP 代理）。
3. **商业版的重资产功能**（云执行、代理池、指纹浏览器、Cookie 上云）既是封号高危区，也是 solo 开源维护者的成本无底洞。
4. **生态位**：MultiPost、Wechatsync 等开源项目证明"本地 + 免费"路线可行且有人用；"开源免费 + 纯本地 + 插件化 + AI 原生（MCP）"的组合目前没有被很好满足。

**结论**：做"本地版 TurboPush + 插件化生态"，砍掉一切云端与防封重资产，用插件化把维护成本分摊给社区。

### 1.4 目标用户

- 个人创作者/自媒体：一文多发（公众号、知乎、CSDN、掘金、B站专栏等），不愿为群发工具付费或上传账号数据。
- 技术用户/开发者：愿意用 CLI/MCP 让 AI 代理编排发布，愿意为平台插件提 PR。
- 小团队（后期）：共享插件与内容模板，但**不做账号托管与团队协作服务端**。

### 1.5 核心用户故事

1. 作为创作者，我在 Seedcast 里写一篇 Markdown，勾选 5 个平台的已登录账号，点一次发布，看到每个平台的成败与作品链接。
2. 作为创作者，我扫码登录一次平台账号，之后长期复用；登录态失效时工具明确告诉我哪个账号需要重新扫码。
3. 作为开发者，我照着插件契约写一个 `manifest.json + selectors.json + flow.json`，就能让 Seedcast 支持一个新平台，不需要改主程序。
4. 作为开发者，平台改版导致发布失败时，我只需更新插件里的选择器 JSON 并提交 PR。
5. 作为 AI 用户（后期），我通过 MCP 让 Claude 直接调用"创建内容 → 选账号 → 发布 → 查回执"。

## 2. 产品形态与技术架构（已定方向）

### 2.1 总体架构

```
┌────────────────────────────────────────────────┐
│  Tauri 2 壳（Rust）                              │
│  窗口/托盘/自动更新/文件对话框/单实例              │
│  ┌──────────────────────────────────────────┐  │
│  │ GUI（React + Vite，系统 WebView）          │  │
│  └──────────────────────────────────────────┘  │
│        │ 本地 HTTP + 随机 Token（仅 127.0.0.1）  │
│  ┌──────────────────────────────────────────┐  │
│  │ 引擎 sidecar（Node + Playwright）          │  │
│  │  插件加载器 · flow 解释器 · 会话池          │  │
│  │  串行任务队列 · 内容渲染 · 回执/记录        │  │
│  └──────────────────────────────────────────┘  │
│        │ CDP（Playwright persistent context）   │
│  ┌──────────────────────────────────────────┐  │
│  │ 用户已安装的 Chrome（每账号独立 profile）   │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
         未来：MCP server 复用同一本地 API
```

### 2.2 关键技术决定与理由

| 决定 | 理由 | 代价/缓解 |
|---|---|---|
| Tauri 2 而非 Electron | 用户指定；壳小、系统 WebView、自动更新成熟 | Playwright 是 Node 库 → 引擎做 sidecar 子进程 |
| Node 引擎 sidecar + Playwright | 浏览器自动化生态最成熟，上传/等待/反检测少手写；社区贡献者最多 | 发行需打包引擎二进制（Node SEA 或 Bun compile）；开发期直接 `node` 跑 |
| 驱动用户已装 Chrome，不捆绑 Chromium | 真实浏览器环境降低风控概率；包体小；学 TurboPush 的 Chrome/Edge 依赖 | 要求用户安装 Chrome（首启检测并引导）；`channel: 'chrome'` |
| 每账号一个 persistent context | 扫码一次长期复用；账号数据 = profile 目录，纯本地可导出 | profile 目录体积管理、损坏恢复 |
| 本地 HTTP + 随机端口/Token | TurboPush 已验证；GUI/引擎解耦；未来 MCP 零成本复用 | 仅绑定 127.0.0.1；Token 每次启动随机 |
| 全局串行队列 | 风控自保；回执与错误归因简单；solo 可维护 | 多平台总耗时线性增长（可接受，明确告知用户） |
| 平台插件两级：声明式 + 代码 | 80% 的平台差异/改版只需改 JSON；复杂平台允许代码接管 | 需定义清晰契约与 apiVersion（§5） |

### 2.3 运行环境

- 桌面：macOS / Windows 为**正式发行目标**；Linux 运行兼容保留，发行包装为后续（P2）。
- 依赖：用户已安装 Chrome（或 Chromium 系浏览器，Edge 支持列为二期）；引擎运行时随包分发，用户无需装 Node。
- 网络：仅访问目标创作平台与插件声明的域名；**无任何自有服务端**。

### 2.4 多平台发行打包（已定）

| 目标 OS | 产物形态 | 签名 / 公证 | 优先级 |
|---|---|---|---|
| macOS 12+（Apple Silicon + Intel） | `.dmg`（或 `.app` 压缩包）；universal 优先，不行则分架构 | Apple Developer 签名 + Notarization | P0（M1 可手工打，M2 自动化） |
| Windows 10+（x64） | `.msi` 或 NSIS `.exe` 安装包 | 代码签名证书（可选但建议；未签名需文档说明 SmartScreen） | P0（同上） |
| Linux | AppImage / deb（后续） | — | P2 |

打包要点：
- **Tauri 2 bundler** 产出壳；**引擎 sidecar** 按目标 OS/架构各打一份二进制，随安装包分发（与 Q4 打包方案绑定）。
- `better-sqlite3` 等原生模块必须按目标平台预编译或在 CI 交叉/矩阵构建。
- CI：GitHub Actions（或等价）矩阵 `macos-latest` + `windows-latest`；tag 触发正式产物上传 Release。
- 自动更新（FR-S4）的 update endpoint 需同时提供 mac / win 产物与签名校验文件。

## 4. 平台覆盖与分期

原则：**架构一次到位，平台分批上线**。先文章（共享 Markdown 管线，边际成本最低），再图文，最后视频（上传工程最重）。

### P1 期 · 文章（MVP 目标）

| 平台 | 难度要点 | 备注 |
|---|---|---|
| 知乎（专栏） | 富文本编辑器写入、话题/专栏设置 | 首个参考插件，声明式 |
| CSDN | Markdown 编辑器原生友好、标签/分类专栏 | 声明式可覆盖 |
| 掘金 | Markdown 原生、分类/标签必填 | 声明式可覆盖 |
| B站专栏 | 富文本、头图/标签 | 声明式 + 少量代码 |
| 微信公众号 | **本期最硬**：内联样式 HTML、图片须传公众号素材库、原创/留言/合集等设置 | 代码插件；渲染器借鉴 doocs/md 思路（引用代码前核对许可证）；仅支持浏览器路线，订阅号/服务号官方 API 路线列为开放问题 |

### P2 期 · 图文

小红书、抖音图文、公众号图文。新增：多图上传与排序、封面规格、位置/话题/声明等动态字段（需查询平台接口或页面提取）。

### P3 期 · 视频

抖音视频、微信视频号。新增：大文件分片上传、断点续传、转码/封面、视频号与公众号关联。工程量最大，单独立项评估。

### 海外平台（不在首批）

YouTube/X 等有官方 API 的平台，未来可做"官方 API 型插件"（不依赖浏览器），契约已预留 adapter 类型字段。

## 5. 插件系统规范（契约草案 v1）

### 5.1 目录结构

```
plugin-<id>/
├── manifest.json      # 必需：元信息、能力声明、入口
├── selectors.json     # 声明式插件：选择器集中管理（改版只改这里）
├── flow.json          # 声明式插件：发布/登录检测步骤
├── schema.json        # 平台设置字段（JSON Schema，供 GUI 渲染表单与校验）
├── index.ts           # 代码插件可选：接管 render/publish 等
└── NOTES.md           # 维护说明：实测日期、已知坑
```

### 5.2 manifest.json 关键字段

```json
{
  "id": "zhihu",
  "name": "知乎",
  "version": "0.1.0",
  "apiVersion": 1,
  "adapter": "flow",            // flow | code
  "contentTypes": ["article"],  // article | imageText | video | audio
  "platform": {
    "home": "https://www.zhihu.com",
    "loginUrl": "https://www.zhihu.com/signin",
    "sessionCheck": {
      "url": "https://www.zhihu.com",
      "loggedInSelector": "...",
      "timeoutMs": 8000
    }
  },
  "capabilities": { "draft": true, "nativeSchedule": false },
  "entry": "index.ts"           // adapter=code 时必填
}
```

### 5.3 flow 步骤词汇（v1，最小集）

`goto` / `waitFor` / `click` / `fill` / `insertText`（富文本键盘注入）/ `press` / `upload` / `select` / `sleep` / `extract`（取属性或文本）/ `currentUrl`。

- 模板变量：`{{title}}` `{{content}}` `{{desc}}` `{{settings.*}}` `{{account.name}}`。
- 选择器一律引用 `selectors.json` 的键，**flow 中不写裸选择器**（保证改版单点修复）。
- 每步失败产出结构化错误（step、selector、截图路径），供回执归因。
- 词汇扩展走 apiVersion 升级，旧插件不受影响。

### 5.4 代码 Adapter 契约（TypeScript）

```ts
interface Adapter {
  meta: PluginManifest;
  checkSession(ctx: Ctx): Promise<boolean>;
  render?(content: Content, settings: Settings): Promise<Rendered>; // 如公众号 HTML
  publish(ctx: Ctx, job: PublishJob): Promise<PublishResult>;       // 可自由使用 Playwright Page
}
// Ctx 提供：page（该账号专属）、content、settings、emit(进度事件)、assets 路径
```

### 5.5 版本与兼容

- `apiVersion` 整数递增；引擎声明支持区间，加载时校验。
- 插件语义化版本；引擎记录"插件 × 引擎"兼容矩阵。
- 官方插件随引擎版本发布；第三方插件独立更新。

### 5.6 安全模型（必须向用户明示）

- 插件在引擎进程内执行，**持有用户账号会话，本质是受信代码，不是安全沙箱**。
- 只安装可信来源插件；第三方插件安装需显式确认 + 风险警示（FR-PL6）。
- 官方插件仓库收录需源码可审；不做闭源插件市场。
- 引擎不向任何第三方发送账号数据；插件网络行为在 manifest 声明域名（提示用，非强制隔离——如实告知局限）。

### 5.7 分发（P2）

git-based 官方索引仓库 `seedcast-plugins`（index.json + 各插件子目录或 submodule），GUI 一键安装/更新；社区 PR 即贡献新平台。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 隐私 | 账号会话、内容、记录全部本地；无自有服务端；默认零遥测 |
| 安全 | 本地 API 仅 127.0.0.1 + 随机 Token；profile 目录权限最小化；更新包签名校验 |
| 性能 | 壳启动 < 2s；引擎冷启动 < 5s；单目标发布耗时取决于平台，进度可见不假死 |
| 可靠性 | 引擎崩溃可被壳检测并重启；发布中断产生明确失败回执而非静默；任务队列持久化（重启可恢复未完成任务为"已中断"） |
| 可维护性 | 选择器与逻辑分离；适配器契约稳定；每插件附实测日期与 NOTES；核心代码测试覆盖 flow 解释器与契约校验 |
| 兼容 | 正式支持 macOS 12+、Windows 10+；Linux 运行兼容、发行 P2；Chrome 最近两个大版本 |
| 发行 | 能在 macOS / Windows 各打出可安装产物；引擎与壳同版本捆绑；原生依赖按平台矩阵构建 |
| 可访问性 | GUI 键盘可达、明暗主题、错误信息可读（不甩堆栈） |

## 7. 明确不做（Non-Goals）

1. **云端发布/云执行**：不做自有服务端，不托管账号 Cookie。
2. **代理池 / 指纹浏览器 / 防封**：不做 IP 伪装与浏览器指纹对抗，不承诺防封。
3. **并发群发/矩阵养号**：全局串行是设计选择，不做多开并发 storm。
4. **付费/VIP/邀请码体系**：永久免费，无功能分层收费。
5. **团队协作服务端、企业 API、数据看板 SaaS**。
6. **移动端 App、浏览器插件形态**（浏览器插件仅作为未来可能的素材采集辅助，另议）。
7. **内容 AI 生成**：Seedcast 只管发布管线；AI 写稿由外部工具经 MCP 接入。
8. **绕过平台验证/验证码打码**：遇到人工验证暂停并提示用户接管。

## 8. 风险与合规

| 风险 | 等级 | 应对 |
|---|---|---|
| 自动化发布违反平台 ToS，账号限流/封禁 | 高 | README 与首启显著声明"风险自负"；串行+低频默认；不做防封承诺；提供仅草稿模式 |
| 平台改版导致适配器失效 | 高（持续） | 选择器单点分离；结构化失败归因；社区 PR 流程；插件实测日期标注 |
| 第三方恶意插件窃取会话 | 高 | 受信代码明示 + 安装确认 + 官方源码可审仓库；不做沙箱虚假承诺 |
| 公众号渲染/素材库规则复杂 | 中 | 代码插件 + 借鉴成熟开源渲染器（先核许可证）；单独里程碑 |
| 视频上传工程量大 | 中 | 推迟到 P3，先做分片上传技术验证 |
| solo 维护燃尽 | 中 | 平台数量克制（P1 仅 5 个）；插件化分摊；明确"不保证所有平台持续可用"的开源免责 |
| 竞品商标/名称混淆 | 低 | Seedcast 已筛查 npm/GitHub；不使用竞品名称与素材 |
| 多平台打包/原生依赖翻车 | 中 | CI 矩阵 early；sidecar 与 better-sqlite3 按 OS 预构建；M1 先手工产物、M2 全自动 |
| macOS 公证 / Win SmartScreen | 中 | 签名密钥仅 CI secrets；未签名时文档明示；正式版再强制公证 |

法律定位：工具本身开源合法（同类项目 MultiPost/Wechatsync 公开存在）；使用行为合规责任由用户承担，文档充分告知。

## 9. 里程碑与验收标准

### M0 · 骨架与契约（约 2–3 周）

交付：monorepo（engine/app/plugins）、Tauri 壳 + 引擎 sidecar 通信、插件加载器 + flow 解释器、知乎参考插件（选择器可为待实测占位）、插件契约文档、GUI 三页（账号/发布/插件）。

验收：
- `pnpm dev` 可同时起引擎与 GUI；壳能拉起/连接引擎（开发模式手动起引擎亦可）。
- 引擎 `/ping` `/plugins` 返回正常；加载知乎插件并校验 apiVersion。
- 用 mock 页面（本地 HTML）跑通一条完整 flow：goto→fill→click→extract，产出回执。
- 契约文档能指导第三方写出可加载的插件。

### M1 · 文章 MVP（约 4–6 周）

交付：知乎/CSDN/掘金 三个**实测可用**的文章适配器 + 内容库/编辑器 + 发布中心 + 记录 + 登录态检测；**macOS / Windows 可手工打出安装包**（含引擎 sidecar）。

验收：
- 真实账号扫码登录后，一份 Markdown 成功发布到 3 个平台并取回作品链接（人工实测记录存 NOTES）。
- 登录态过期时发布前拦截并给出重扫引导。
- 任一平台改版模拟（改选择器）→ 失败回执准确定位步骤，仅改 selectors.json 可修复。
- 全程无数据出本机（抓包自查）。
- 在 macOS 与 Windows 各至少打出一份可安装产物，安装后能启动壳并连接引擎（签名可暂缓）。

### M2 · 公众号 + 图文（约 6–8 周）

交付：公众号代码插件（内联样式渲染 + 素材库上传）、B站专栏、小红书/抖音图文；草稿与平台原生定时、dry-run 预览、数据导出导入、自动更新；**CI 矩阵自动产出 mac/win 正式包**（含签名/公证流程文档）。

验收：公众号文章含 3 张图片成功发布且样式正常；图文多图顺序正确；定时发布在平台后台可见；tag 发布可下载 macOS dmg 与 Windows 安装包。

### M3 · 视频 + 生态（评估后排期）

交付：抖音/视频号视频上传、MCP server、CLI、官方插件索引与一键安装、插件脚手架。

验收：100MB 视频成功上传发布；Claude 经 MCP 完成"建内容→发布→查回执"闭环；社区按文档提交的新插件可被加载。

## 10. 数据模型（草案）

```
Content  { id, title, markdown, assets[], createdAt, updatedAt }
Account  { id, pluginId, name, profileDir, lastCheckAt, status }
Task     { id, contentId, targets[{pluginId, accountId, settings}],
           status: pending|running|done|interrupted, createdAt }
Receipt  { taskId, target, ok, url?, error?: {code, step, selector?, screenshot?}, at }
Plugin   { manifest, dir, source: builtin|local|registry, enabled }
```

存储：**本地 SQLite**（`~/.seedcast/db/seedcast.sqlite`），引擎内嵌访问（建议 `better-sqlite3` 或等价同步驱动）。

| 存 SQLite | 仍为文件系统 |
|---|---|
| Content / Account / Task / Receipt / 插件启用态与来源元数据 | Chrome profile（`profiles/`）、内容素材（`assets/`）、插件包目录、`engine.json`（端口/Token） |

- 库内复杂字段（如 `assets[]`、`targets[]`、`error`）以 JSON 文本列存放，表结构保持扁平、易迁移。
- 导出/导入：打包 sqlite 文件 + profiles + assets + plugins（见 FR-S2）。
- Schema 版本用库内 `schema_version` 表管理，引擎启动时跑迁移。

## 11. 本地 API 草案（GUI 与未来 MCP 共用）

```
GET  /ping                      健康
GET  /plugins                   已加载插件
GET  /accounts?plugin=          账号列表
POST /accounts/login            {plugin, name} → 打开登录浏览器
GET  /accounts/session          ?plugin&account → 登录态
CRUD /contents                  内容库
POST /publish                   {contentId, targets[]} → SSE: info/success/error/finish
GET  /records                   发布记录与回执
```

认证：`Authorization: <token>`；端口与 Token 每次启动随机，写入 `~/.seedcast/engine.json`（仅当前用户可读）。
