# Seedcast 开发计划

- 基于：`docs/需求文档.md` v0.1
- 日期：2026-11-21
- 假设：solo / 小团队，每周约 20–30h 有效开发
- 原则：**架构一次到位，平台分批上线；先文章管线，再图文，最后视频**

---

## 0. 总览

| 里程碑 | 目标 | 工期（估） | 出口标准（摘要） |
|---|---|---|---|
| **M0** 骨架与契约 | monorepo + 壳/引擎通信 + 插件契约 + mock flow | 2–3 周 | `pnpm dev` 通；mock flow 出回执；契约可加载插件 |
| **M1** 文章 MVP | 内容库 + 账号 + 发布 + 知乎/CSDN/掘金实测 + mac/win 手工打包 | 4–6 周 | 一份 MD 发到 3 平台；双系统可安装启动 |
| **M2** 公众号 + 图文 | 公众号/图文 + 草稿/定时/导出/更新 + CI 自动打 mac/win 包 | 6–8 周 | 公众号含图；Release 可下 dmg + win 安装包 |
| **M3** 视频 + 生态 | 视频上传、MCP、CLI、插件仓库与脚手架 | 评估后排期 | 100MB 视频 + MCP 闭环 + 社区插件可加载 |

```
M0 ──► M1 ──► M2 ──► M3
 │      │      │      │
 契约   文章   公众号  视频
 骨架   MVP    图文    MCP/CLI
```

**不做清单（全程遵守）**：云端执行、代理/指纹、并发矩阵、收费体系、团队服务端、内容 AI 生成/知识库工坊、验证码打码。

**GUI 布局（已定）**：学 TurboPush 信息架构——左侧主导航 + 右侧操作区；顶栏创作/快速发布；账号库可二级拆分。详见 `docs/需求文档.md` §3.5.1 与附录 B。

## 1. 技术底座（开局即定）

| 层 | 选型 | 包名建议 |
|---|---|---|
| 壳 | Tauri 2（Rust） | `@seedcast/app`（前端）+ `apps/desktop` |
| GUI | React + Vite + TypeScript | 同上 |
| 引擎 | Node + Playwright（sidecar） | `@seedcast/engine` |
| 插件 | 声明式 flow / 代码 Adapter | `@seedcast/plugin-*` |
| 共享类型/契约 | TypeScript | `@seedcast/shared` |
| 包管理 | pnpm workspace | 根 `pnpm-workspace.yaml` |
| 数据目录 | `~/.seedcast/` | `db/seedcast.sqlite`、profiles、assets、plugins、engine.json |
| 本地库 | SQLite（`better-sqlite3` 建议） | Content/Account/Task/Receipt/插件元数据；素材与 profile 仍走文件系统 |
| 发行目标 | macOS 12+（arm64+x64）、Windows 10+（x64） | Tauri bundler + 引擎 sidecar；Linux 发行 P2 |
| CI 打包 | GitHub Actions 矩阵 | `macos-latest` + `windows-latest`；tag → Release 产物 |

### 1.1 建议 monorepo 结构

```
multipublisher/                 # 工作区（将来可改名 seedcast）
├── docs/                       # 需求/计划/changelog（随仓库发布）
├── code/                       # = GitHub owlteam990/seedcast 源码根
│   ├── apps/
│   │   └── desktop/            # Tauri 2 + React GUI
│   ├── packages/
│   │   ├── engine/             # sidecar：HTTP API、队列、flow、会话
│   │   ├── shared/             # 类型、契约、常量、错误码
│   │   └── plugin-sdk/         # Adapter 类型、脚手架模板依赖
│   ├── plugins/
│   │   ├── mock/               # M0 fixture
│   │   ├── zhihu/
│   │   └── ...
│   ├── LICENSE                 # Apache-2.0
│   ├── package.json
│   └── pnpm-workspace.yaml
├── LICENSE                     # 与 code/ 一致（仓库根）
└── README.md
```

**仓库约定：** 远程 `https://github.com/owlteam990/seedcast`；**第一版完成前不 push**。`.gitignore` 排除日志、本地数据、临时测试脚本/产物（见根目录忽略规则）。

### 1.2 开局前需拍板的开放问题（阻塞度）

| ID | 问题 | 建议默认 | 最晚决策点 |

| Q4 | 引擎打包 Node SEA vs Bun | 开发期用 `node`；**M0 末验证且须出 darwin+win32** | M0 结束前 |

## 7. 本地 API 落地顺序

按客户端依赖排序（GUI 即第一客户端）：

| 阶段 | 接口 | 里程碑 |
|---|---|---|
| 健康 | `GET /ping` | M0 |
| 插件 | `GET /plugins` | M0 |
| 账号 | `GET/POST /accounts*`、`GET /accounts/session` | M1 |
| 内容 | CRUD `/contents` | M1 |
| 发布 | `POST /publish`（SSE） | M1 |
| 记录 | `GET /records` | M1 |
| 管理扩展 | 插件启停、导出导入、dry-run 等 | M2 |
| MCP/CLI | 复用同一 API | M3 |

## 8. 人力与关键路径（solo）

若单人开发，建议严格串行，避免并行开多个硬平台：

```
M0 全做完
 → M1：内容/账号/发布骨架 → 知乎 → CSDN → 掘金 → 打磨
 → M2：公众号（整段专线）→ B站 → 图文两家 → 体验功能
 → M3：Spike 后再排期
```

**并行仅限**：GUI 页面与引擎 API 在契约稳定后可前后端并行；声明式插件在 flow 稳定后可一人写插件、一人写 GUI。

**缓冲**：每个里程碑预留约 20% 时间给平台改版与不可预期的选择器失效。

## 10. 风险应对（开发侧）

| 风险 | 开发侧动作 |
|---|---|
| 平台改版高频 | 选择器集中；失败归因到 step；官方插件小步发版 |

| 恶意插件 | 安装确认 UI；不做沙箱虚假承诺；官方源码可审 |
| 跨平台原生依赖 | CI 矩阵 early；sidecar/`better-sqlite3` 按 OS 预构建；M1 手工、M2 自动化 |
